@purpose
**Fit figures.** Makes every figure's text readable (at least 7 pt when printed) and keeps every figure inside its column, without the user touching LaTeX. If readable figures push the paper over the page limit, it can also make a second layout that stays within the limit.

The idea, in steps:
- compile once with markers, and **measure** each figure: its width and its text size per point of width;
- **plan** a target width for each figure: wide enough that its text reaches 7 pt, but no wider than its column; if even a full column is not enough, make it span both columns (`figure*`); if even the full page is not enough, say the figure must be re-exported with bigger fonts;
- compile the paper at those widths; if it goes over the page limit, **binary search** between the smallest acceptable widths (t = 0) and the targets (t = 1) for the largest t that still fits;
- measure again and report what changed.

Constants: `SEARCH_STEPS = 5` halvings of the search range (5 extra compiles); `SLACK = 2` pt (aim 2 pt above the minimum, and ignore changes under 2 pt); `LIMIT_FLOOR = 0.4` (the "within the limit" layout may shrink a figure to 40% of its column).

@imports
`math` (floor), `Path`, `pymupdf` (count pages), `compile_pdf`, the figure tools (`find_graphics`, `instrument`, `resize`), `measure`, and the `FigureChange`, `FitReport`, `Rules` classes.

== FitFailed
Raised when fitting cannot work: no graphics, no geometry, or a layout that did not compile.

== _compile
Writes a temporary .tex next to the paper, compiles it, and deletes the .tex **whatever happens** (`finally`). Raises `FitFailed` if no PDF came out.
? What does finally do?
! Its code runs whether the try block succeeded or raised an error, so the temporary file is always removed.
? Why write the file next to the paper and not in a temp folder?
! LaTeX finds images relative to the .tex file; next to the paper, `media/...` paths still work.

== _pages
Opens a PDF and returns its page count.

== _last_page_fill
How full the last page is, from 0 to 1: the lowest bottom edge of any text block or image on it, divided by the page height. Used to say "about 1.4 pages over" instead of just "2 pages".
? Why measure the last page?
! A paper with a 7th page that is only 30% full is about 0.3 pages over, not 1 whole page.

== _width_expr
Turns a width in points into LaTeX relative to the column or page, rounded **down** to three decimals: 180 pt in a 252 pt column becomes `0.714\columnwidth`.
? Why round down instead of to the nearest?
! Rounding up could make the figure a hair wider than allowed and overflow its column.
? What does :g do in the format?
! It prints the number without trailing zeros: 0.5 not 0.500.

== plan
Decides one figure's target width, whether it spans both columns, its smallest acceptable width (`floor`) and a note.
- **limit policy:** keep the current width (at most the column) and allow shrinking to 40% of the column.
- **readable policy:** `k` is text size per point of width, so the width that gives `min_pt` text is `min_pt / k`; 2 pt of slack is added.
- Needs more than the whole page: impossible, keep it in its column and say "re-export it with larger fonts".
- Needs more than one column: switch to two columns.
- A width within 2 pt of the maximum is left as it is (no pointless 1 pt changes).
- No text found: only keep it inside its column.
> k = 0.025 pt per pt, min 7 pt  ->  smallest = 7 / 0.025 + 2 = 282 pt  >  column 252  ->  figure*
* Strategy pattern (simple form): the `policy` argument chooses between two ways of sizing figures, "readable" and "limit", without separate code paths in the caller.
? How is the needed width calculated?
! Text size grows with width: text = k times width. For 7 pt text, width = 7 / k, plus 2 pt slack.
? When does a figure become figure*?
! When the width needed for readable text is wider than one column but fits the page.
? What if even the full page is too narrow?
! The figure is kept in its column and the note says to re-export it with larger fonts; shrinking cannot help.

== fit_paper
The whole fitting run for one policy; returns a `FitReport`.
- Finds graphics, compiles an instrumented copy, measures, reads the geometry and page count.
- For each graphic: a `FigureChange` with the before values; graphics that cannot be resized get a "left alone because..." note; the others get a target and floor from `plan`.
- Nested `layout(t)` gives each figure the width `floor + t * (target - floor)`: t = 0 is all floors, t = 1 is all targets. Only real changes are included.
- Nested `pages_at(t)` compiles that layout and counts pages.
- If the targets fit, done. If not, and even the floors do not fit, the summary says how many pages to cut. Otherwise a **binary search** over t finds the largest layout within the limit.
- The chosen layout is written to `-fitted.tex` (or `-fitted-limit.tex`), measured again for the "after" values, and compiled to the final PDF.
* Algorithm: binary search over a scale t, because each test costs a full LaTeX compile.
? What is the binary search searching for?
! The largest scale t between 0 and 1 for which the paper still fits the page limit. Each step compiles the middle value and keeps the half that contains the answer.
? Why 5 steps?
! Each step halves the range: after 5 steps it is 1/32 wide, precise enough, and each step costs a full compile.
? What happens if the smallest readable figures still do not fit?
! The report says roughly how many pages over the paper is and asks the author to cut text or figures, instead of making the figures unreadable.
? Why measure again after fitting?
! The plan is a prediction; measuring the real result shows the true text size and catches any remaining overflow.

== _size
Points to inches as text: 252 pt is "3.50 in" (72 points per inch).

== describe
Turns a FitReport into the lines shown in the Figure fit tab: for each figure, its size, columns and text size before and after (or "unchanged"), a warning if text is still below the minimum, and the note; then the page count before and after and the summary.
- `span` and `text` are small lambdas used to format values.
> Fig. 4 (page 3): 3.40 in, one column, text 3.9 pt  ->  7.12 in, both columns, text 7.0 pt
? Why is c.name used with a fallback?
! `Project.fit` names each change by its figure number in the paper ("Fig. 4"); if no name was set, the graphic's index is used.
