@purpose
Reads **who wrote the paper**. It gets the short lines from the top of a paper (after the title) and decides which lines are author names and which are affiliations or emails, then returns a list of `Author` objects. It also has `latex_to_plain`, which strips LaTeX commands out of a piece of text.

Three patterns at the top matter:
- `_MARKER` finds affiliation marks: superscript digits ¹², symbols * † ‡ § ‖, or digits glued to the end of a name ("Sharp1").
- `_LABEL` finds a label line like "Authors:" or "Author(s):", which is skipped.
- `_NAME_WORD` describes one word of a name: a capital followed by lowercase letters (hyphens and apostrophes allowed, accents à to ÿ allowed), or an initial like "R." or "R.R.".
`_ORGANISATION` is a set of words like "university" and "department": a line containing one is not a name.

@imports
Only `re` and the `Author` class from `models.py`.

== latex_to_plain
Turns a LaTeX snippet into plain text, for example an IEEE author block.
- `\label{...}` and `\textsuperscript{...}` are removed.
- `\\` (LaTeX line break) is replaced by a temporary invisible character `\x00`, so line breaks survive the cleaning and become real newlines at the end.
- `~` (non-breaking space) becomes a space; escaped characters like `\%` become `%`.
- The `while previous != text` loop removes commands like `\textbf{X}` leaving `X`, **again and again** until nothing changes, so nested commands such as `\emph{\textbf{X}}` are fully unwrapped.
- `---` and `--` become proper dashes.
> latex_to_plain("Asha Rao\\\\ \\textit{Dept. of CS}, DA-IICT")  ->  "Asha Rao\nDept. of CS, DA-IICT"
? Why the loop `while previous != text`?
! Each pass unwraps one layer of commands. Repeating until the text stops changing handles any nesting depth.
? Why replace `\\` with "\x00" first?
! The cleaning would destroy the line breaks; a character that never appears in real text keeps their place until the end.

== _looks_like_a_name
Says whether a short piece of text looks like a person's name.
- 2 to 4 words, no digits, no "@".
- No organisation word (university, department...).
- Every word matches `_NAME_WORD` (capital then lowercase, or an initial).
> _looks_like_a_name("Renas Rajab Asaad")  -> True
> _looks_like_a_name("Nawroz University")  -> False   (organisation word)
? Why limit names to 2 to 4 words?
! One word is rarely a full name and five or more is usually a sentence or an affiliation.
? What does `all(...)` return for these words?
! True only if every word passes `re.fullmatch(_NAME_WORD, w)`.

== _split_marks
Splits a name from its affiliation marks: "Sharp¹²" becomes ("Sharp", {"1","2"}).
- `_MARKER.finditer` finds every mark; superscript digits are turned back into normal digit strings using their position in `_SUPERSCRIPTS`.
- Symbols like * or † are kept as they are.
- The name is cleaned with `_clean_name`.
? Why turn ¹ into "1"?
! The affiliation line later starts with "1 Northern Arizona University"; both sides must use the same key to match.
? Why a set for the marks?
! Order does not matter and each mark should count once.

== _clean_name
Removes leftovers around a name: a leading "1st " / "2nd " (some templates number authors), and stray commas, digits, stars and superscripts at either end (`strip` removes any of the listed characters from both ends).
? What does str.strip(chars) do with a string argument?
! It removes any of those characters from both ends, in any order, until a character not in the set is met.

== read_authors
The main author reader. It walks every line of every paragraph and decides what the line is. It keeps:
- `authors`: the result list;
- `group`: the authors most recently found (affiliation lines attach to them);
- `marks`: which marks each author carries, keyed by `id(author)` (the object's identity).
For each line, the first rule that fits wins:
- empty or an "Author(s):" label: skip;
- starts with a mark ("¹ Northern Arizona University") and we know marks: attach it to every author carrying that mark;
- contains "@" or starts with "Email": attach to the current group;
- several names separated by commas or "and": a new group of authors;
- one name (alone, or first on its line followed by commas): a new author; on the first line the rest of the line is the affiliation;
- no author yet: take the line as a name anyway;
- otherwise: it is an affiliation line for the current group.
The nested `attach` joins text onto each author's affiliation with ", ".
> ["Sharp¹, Lee² and Park¹", "¹ Northern Arizona University", "² MIT"]
> -> [Author("Sharp","Northern Arizona University"), Author("Lee","MIT"), Author("Park","Northern Arizona University")]
? Why key marks by id(author) and not by name?
! Two authors can share a name; `id` is unique to each object while it exists.
? What happens to an email line?
! It is attached to the latest group of authors as part of their affiliation.
? Why is `group or authors[-1:]` used?
! If there is no current group, fall back to the last author; `authors[-1:]` is a list with the last author, or empty if there are none (no crash).

== title_and_authors
The first non-empty paragraph is the title (spaces squeezed, quotes stripped); the rest go to `read_authors`. Returns `(title, authors)`.
? What does it return for no paragraphs?
! `("", [])`: an empty title and no authors, which the analyzer then reports as missing.
