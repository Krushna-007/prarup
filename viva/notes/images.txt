@purpose
Checks every figure image of the paper. For each image it measures the **printed resolution** (dpi), finds **duplicates**, and looks for **evidence that it was made by AI**, in three layers, strongest first:
- **Layer 1, declared:** a signed C2PA manifest ("Content Credentials") saying a generative AI made it, or the IPTC tag `trainedAlgorithmicMedia` in the image's metadata. Google's Gemini signs its images this way.
- **Layer 2, traces:** settings a generator leaves in the file: Stable Diffusion's `parameters` text in a PNG, a ComfyUI workflow, or a generator's name in the metadata.
- **Layer 3, classifier (optional install):** a trained model that gives a likelihood. It is run only on photo-like images, because on 26 real paper figures it gave 4 false alarms on charts.
The report always says "evidence", never "this is AI": finding nothing proves nothing, because Word and screenshots strip metadata.

Numbers to remember: an IEEE column is 3.5 inches wide; IEEE asks for at least 300 dpi; two images whose hashes differ in at most 4 of 64 bits are "the same picture"; a picture whose 8 most common colours cover 90% of its pixels is a chart.

@imports
`json` (the C2PA library returns JSON), `re`, `dataclass`, `Path`, Pillow's `Image` (open images, read metadata) and `ImageOps` (grayscale), `Finding` from analyze (findings use the same class as missing-data findings, so the window shows them the same way), and `Manuscript`. The `c2pa`, `torch` and `transformers` libraries are imported **inside** the functions that use them, so Prarup still runs if they are not installed.

== ImageReport
Everything found about one image file: path, which block and figure number, pixel size, printed width in inches, dpi, the three AI layers (`declared`, `traces`, `ai_score` with `ai_note`), `duplicate_of`, and whether the file could be read. A dataclass, so the fields are listed once.
? Why `ai_score: float | None` and not just a float?
! None means "the classifier did not run" (not installed, or a chart). 0.0 would wrongly mean "ran and found nothing".

== ImageReport.verdict
One short phrase summarising the evidence, strongest layer first: declared, then traces, then a classifier score of at least 0.8, otherwise "no AI evidence found".
? Why is declared checked before the classifier?
! A signed statement from the generator is proof of origin; a classifier score is only a guess. The strongest evidence is reported first.

== read_c2pa
Reads the C2PA manifest with the `c2pa` library, if the file has one. It looks in the active manifest's `c2pa.actions` for an action whose `digitalSourceType` ends with an AI type, and returns a sentence with what was done, who signed it and whether the signature is valid. Any problem (library missing, no manifest) returns "".
> "C2PA Content Credentials: Created by Google Generative AI.; signed by Google C2PA Core Generator Library; signature valid"
? Why is `import c2pa` inside the try?
! If the library is not installed the import fails, and the function just returns "" instead of crashing the program.
? What is C2PA?
! An industry standard for signed provenance: the tool that made the image attaches a cryptographically signed record of how it was made.

== metadata_text
Collects every piece of text metadata in the image into one string: PNG text chunks (`image.info`), EXIF values, and XMP packets (an XML block found in the raw bytes with a regex). Later functions search this string.
? What is XMP?
! An XML block of metadata embedded in the file. The IPTC "digital source type" lives there.

== find_traces
Looks for layer-2 evidence: Stable Diffusion's `parameters` chunk (returns its "Steps: ..." line), a ComfyUI `workflow` chunk, or a known generator name anywhere in the metadata.
> "Stable Diffusion settings in the PNG: Steps: 30, Sampler: Euler a, CFG scale: 7..."
? Is a generator name in metadata proof?
! No. It is a trace, reported as a warning, not an error. Only a signed declaration is reported as an error.

== classifier_installed
True if both `torch` and `transformers` can be imported. The window uses it to disable the "AI classifier" tick box when they are missing.
? How do you test if a library is installed without crashing?
! Try to import it inside try/except ImportError.

== ai_score
Runs the classifier on one image and returns the probability that it is AI-generated, or None if not installed.
- `global _model`: the model is loaded once (slow, from disk) and kept in a module-level variable for later calls.
- The pipeline returns labels with scores; the one whose label means "AI" is returned.
* Lazy initialisation: the model is created on first use and reused (a module-level cache, like a singleton).
? Why global _model?
! Loading the model takes seconds; keeping it in a module-level variable means it is loaded on the first call only.
? What does `global` do?
! It lets the function assign to the module-level name instead of creating a new local variable.

== photo_like
Decides if an image is a photo (or AI art) rather than a chart, diagram or logo. It shrinks the image to at most 256 px, groups each pixel's colour into coarse bins (each channel divided by 32, so 8 levels), counts the bins, and checks how much of the image the 8 most common bins cover. Charts use few flat colours (measured 0.94 to 1.00); photos use many (0.47 to 0.89). Below 0.9 means photo.
? Why does the classifier skip charts?
! It was trained on photos and art. On real paper charts it gave scores up to 1.00, which would wrongly accuse honest authors.
? Why divide each colour by 32?
! It merges nearly identical shades into one bin, so anti-aliasing around lines does not count as new colours.

== dhash
The **difference hash** of an image: shrink it to 9 by 8 grey pixels, then for each row compare each pixel with its right neighbour (brighter or not). 8 rows times 8 comparisons give 64 bits. Resizing or recompressing a picture barely changes these bits, so near-identical pictures get near-identical hashes.
- `bits = (bits << 1) | (...)` shifts the number left one place and puts the new bit at the end.
? Why compare neighbours instead of storing the pixels?
! The pattern of "brighter than the next pixel" survives resizing, brightness changes and JPEG compression; raw pixel values do not.
? What does << 1 do?
! Shifts the bits left by one, which is the same as multiplying by 2, making room for the next bit.

== same_picture
Two hashes are the same picture if at most 4 of their 64 bits differ. `a ^ b` (XOR) has a 1 wherever they differ; `bin(...).count("1")` counts them. This count is the **Hamming distance**.
? Why allow 4 bits of difference and not 0?
! A resized or re-saved copy changes a few bits. A threshold of 4 caught real duplicates in tests without matching different figures.

== inspect_file
Everything about one image file: size, metadata, layer 1 (C2PA, then IPTC tag), layer 2 traces, then the classifier only if asked and only if `photo_like`. Returns the report and the dhash (None if the file could not be read). Any error (a PDF figure, a damaged file) marks the report unreadable instead of crashing.
* Open/Closed in practice: each AI layer is its own function (`read_c2pa`, `find_traces`, `ai_score`); a fourth layer is one more function and one more line here.
? Why return the hash separately instead of storing it in the report?
! Only `inspect` needs it, to compare images with each other; the report is what the user sees.

== inspect
Runs `inspect_file` on every image of every figure.
- `share`: each image's printed width is assumed to be the column width (3.5 in times 0.98) divided by the number of images in its figure. If a measured width is given in `printed`, that is used instead.
- dpi = pixels / printed inches.
- Each new hash is compared with all earlier ones; the first close one is recorded as `duplicate_of`.
- Missing files and PDF figures (vector, no pixels) are skipped.
> 400 px printed 3.43 in wide  ->  117 dpi  ->  below 300, a warning
? How is printed dpi calculated?
! Pixel width divided by printed width in inches. A 400 px image printed 3.43 in wide is about 117 dpi.
? Why skip PDF figures?
! They are vector drawings: they have no pixels, so dpi does not apply.

== findings
Turns the reports into `Finding`s the window can list: IMG-01 low dpi, IMG-02 declared AI (an error), IMG-03 generator traces, IMG-04 classifier at least 80%, IMG-05 duplicate, IMG-06 unreadable. The nested `add` builds each message with the figure name in front.
* DRY: image problems use the same `Finding` class as missing-data problems, so the window shows both with the same code.
? Why is IMG-02 an error but IMG-03 a warning?
! IMG-02 is a signed declaration: the image certainly came from a generator, which needs disclosure. IMG-03 is only a trace and might be wrong.
? Why `elif` between IMG-02, 03 and 04?
! Only the strongest AI evidence is reported, so one image does not get three AI warnings.
