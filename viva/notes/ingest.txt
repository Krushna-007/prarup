@purpose
This file turns a paper (Word, LaTeX, or a zip of a LaTeX project) into a `Manuscript`: a title, authors, abstract, keywords, and a list of tagged `Block`s (heading, para, figure, table, equation, list, references...). It is the heart of "reading the paper".

The order of work, all started by `open_paper` at the bottom of the file:
- unzip if needed, then ask pandoc for the JSON tree (`pandoc.read`);
- `_flatten` removes wrapper boxes (Divs) so the blocks are one flat list;
- `_front_matter` (Word) or `_tex_front_matter` (LaTeX) finds title, authors, abstract and keywords;
- `_body` walks the rest and decides what each block is;
- `_to_markdown` turns every block's text into Markdown, the one format Prarup edits;
- for LaTeX, images and the bibliography are copied into the project folder.

The patterns at the top are regular expressions compiled once with `re.compile` (faster than compiling inside a loop). `re.I` means ignore case; `re.S` lets `.` match newlines too.
- `_FIG_CAPTION` matches "Fig. 3: text", "Figure 3. text", "Figures 4 a and b text". Group 1 is the number, group 2 the caption text.
- `_STRICT_CAPTION` is stricter: it needs a separator (`:` `.` `-`) and then text. Used for captions whose image is missing, so a sentence like "Figure 3 shows..." is not taken as a caption.
- `_TAB_CAPTION` matches "Table 2: text" or "Table II. text" (Roman numerals, as IEEE writes them).
- `_REFERENCES`, `_ABSTRACT`, `_KEYWORDS` match those words on their own line, in any case.
- `_EQ_NUMBER` matches an equation number like "(2)".
- `IMAGE_EXTENSIONS`: LaTeX lets you write `\includegraphics{figs/plot}` with no extension, so these are tried in turn.

@imports
`re` for every pattern, `shutil` to copy image and .bib files, `zipfile` to open a zipped LaTeX project. From Prarup: `pandoc` (read the paper, convert text), `texsource` (read things straight from LaTeX source that pandoc loses, such as IEEE author blocks and \bibitem lists), three helpers from `frontmatter` for title and authors, and the `Block` and `Manuscript` classes it fills in.

== OpenFailed
Our own exception for a paper Prarup cannot open: wrong file type, unsafe zip, no main .tex file. The window shows its message to the user.
? Where is OpenFailed raised?
! In `open_paper` (wrong extension), `_unzip` (unsafe path) and `_main_tex` (no main file).

== _unspace
Some Word templates write headings with spaces between letters: "A B S T R A C T". This joins capital letters separated by single spaces back into a word.
- The pattern `\b(?:[A-Z] ){2,}[A-Z]\b` means: at least three capitals each followed by a space, then a final capital.
- The replacement is a **lambda** that takes the match and removes its spaces.
> _unspace("A B S T R A C T Diabetes is...")  ->  "ABSTRACT Diabetes is..."
? Why a lambda as the replacement and not a string?
! The replacement depends on the matched text (remove its spaces); a function can compute that, a fixed string cannot.
? Why {2,}?
! It needs at least two "letter space" pairs before the last letter, so normal words like "A B" in a sentence are left alone.

== _images
Finds every image inside any piece of the pandoc tree and returns `(path, attributes)` pairs. It uses the same recursive `walk` idea as `pandoc.stringify`.
- In pandoc, an Image node's content is `[attr, alt_text, [path, title]]`, so the path is `n["c"][2][0]`.
- `attr` is `[id, classes, key_value_pairs]`; `dict(n["c"][0][2])` turns the pairs into a dict, for example `{"width": "3in"}`.
? What does dict() do with a list of pairs?
! `dict([["width","3in"]])` builds `{"width": "3in"}`: each pair becomes a key and value.

== _image_only
Returns the images of a paragraph if the paragraph is **only** images (Word puts a picture in its own paragraph). Otherwise returns an empty list.
- It counts words. Single letters like "(a)" or "b." are not counted: they are sub-figure labels.
- `images and words == 0` is true only when there is at least one image and no real words.
? Why are "(a)" labels not counted as words?
! Word papers often put "(a)" under each sub-image; those paragraphs are still image paragraphs.
? What does re.fullmatch do?
! It matches only if the **whole** string fits the pattern, not just the start.

== _bold_heading
Many Word papers make section titles as a bold paragraph instead of a real Heading style. This spots them.
- Every non-space piece must be `Strong` (bold).
- The text must be 2 to 90 characters, must not end like a sentence (`.` `,` `;`), and must not look like a figure caption.
- If all that holds, it returns the inner words (the contents of the bold pieces), which become the heading text.
- `[x for i in inner for x in i["c"]]` is a nested list comprehension: for each bold piece, take each word inside it.
? Why reject text ending with a full stop?
! A bold sentence in the body is emphasis, not a heading. Headings rarely end with a full stop.
? How do you read `[x for i in inner for x in i["c"]]`?
! Left to right like two for loops: for i in inner: for x in i["c"]: collect x. It flattens a list of lists.

== _named_section
Spots a plain line like "Introduction:" or "3. Results and discussion" that is really a section heading. `_SECTION_NAMES` lists common section names; an optional number or Roman numeral may come first. Returns the clean name, without the colon.
? Why was this needed?
! A real Zenodo paper wrote "Introduction:" and "Conclusion:" as ordinary paragraphs; without this they were not headings.

== _equation
Decides whether a paragraph is an equation: exactly one maths piece, and anything else must be an equation number like "(2)". Inline maths only counts if it has a number next to it.
- `maths[0]["c"]` is `[math_type, latex]`; the type is `DisplayMath` or `InlineMath`.
- Returns the LaTeX of the equation, or None.
? Why is inline maths without a number not an equation?
! Inline maths appears inside normal sentences ("where $x$ is..."). Only a displayed formula, or one numbered like "(2)", is an equation block.

== _flatten
pandoc wraps some content in `Div` boxes. This removes the boxes and keeps their children, so the rest of the code sees one flat list. Two kinds of Div are kept whole: IEEE keywords and the bibliography (`thebibliography`, or a Div with id `refs`), because `_body` handles them as a unit.
- It calls itself on the Div's children: **recursion**, because Divs can be nested.
- `{"IEEEkeywords", "thebibliography"} & set(classes)` is a set intersection: non-empty if any class matches.
? Why does _flatten call itself?
! A Div can contain another Div; calling itself handles any depth.
? What does & mean between two sets?
! Intersection: the items in both sets. An empty set counts as False in an if.

== _main_tex
In an unzipped project, finds the main .tex file: the first one (shallowest folder first) that has both `\documentclass` and `\begin{document}`.
- `sorted(..., key=lambda p: len(p.parts))` sorts by folder depth, so `main.tex` at the top is tried before `sections/intro.tex`.
- `errors="replace"` means a strange byte does not crash reading; it becomes a placeholder.
? Why sort by len(p.parts)?
! `parts` is the list of folder names in the path. Fewer parts means nearer the top, where the main file usually is.

== _unzip
Unpacks a zipped LaTeX project safely, then finds the main file.
- Before extracting, every name in the zip is checked: its full path must stay inside the target folder. A name like `../../etc/passwd` would escape it ("zip slip"), so that raises `OpenFailed`.
- `with zipfile.ZipFile(...) as z` closes the zip automatically afterwards.
* Defensive programming: every path is checked before extracting (zip-slip protection).
? What is zip slip?
! A zip entry whose name uses `../` to write files outside the folder you unzip into. We resolve each path and refuse any that leaves the folder.
? Why use with?
! It guarantees the file is closed even if an error happens inside the block.

== _front_matter
For Word papers: finds the abstract and keywords, then reads everything above the abstract as title and authors. Returns how many blocks it used, so the body starts after them.
- It only looks at the first 30 blocks (`window`).
- It searches for a paragraph starting "Abstract", or a table containing "ABSTRACT" (some templates put the abstract in a layout table). It stops at the first real heading.
- **No abstract found:** it takes the short paragraphs before the first heading as title and authors, and adds a note saying so.
- **Abstract in a table:** the cells are split on newlines; the longest cell over 200 characters is the abstract; the cell after "Keywords" is the keywords.
- **Abstract as a paragraph:** the text after the word "Abstract", or the next paragraph if the heading was on its own.
- Logos (image-only paragraphs above the title) are left out and noted.
- The remaining paragraphs above the abstract go to `title_and_authors`.
? Why only the first 30 blocks?
! The title block is always at the start. Looking further would risk taking a body paragraph as an author.
? What does the function return, and why?
! The index of the first body block. `open_paper` cuts the list there so the title block is not repeated in the body.
? How does it handle the SVM paper's abstract table?
! It finds a Table containing "ABSTRACT", takes the longest long cell as the abstract and the cell after "KEYWORDS" as keywords.

== _marks_to_unicode
IEEE LaTeX author blocks mark affiliations with superscripts: `$^{1,2}$` or `\textsuperscript{*}`. This turns them into Unicode characters (¹²) so the author reader can match names to affiliations.
- `str.maketrans` (the `_SUPER` table above) maps "0".."9" to "⁰".."⁹"; `translate` applies it.
- `_SYMBOLS` maps `\dagger` to †, `\ddagger` to ‡ and so on.
- It has a nested function `convert` used as the replacement for two patterns.
> _marks_to_unicode("Asha Rao$^{1}$")  ->  "Asha Rao¹"
? What do maketrans and translate do?
! `maketrans` builds a character-to-character table; `translate` replaces every character found in the table.

== _tex_front_matter
For LaTeX papers: the title and abstract come from pandoc's metadata (`doc["meta"]`). Authors do not survive pandoc well in IEEE style, so `texsource.ieee_author_blocks` reads them straight from the source, the marks are converted to Unicode, the LaTeX is turned into plain text, and `read_authors` matches names to affiliations.
? Why not take authors from pandoc's metadata?
! IEEE's `\IEEEauthorblockN` and `\IEEEauthorblockA` are not understood by pandoc, so the names and affiliations are read from the source text instead.

== _resolve
Finds the real image file for a path written in LaTeX.
- Tries the path with each extension in `IMAGE_EXTENSIONS`.
- If a file is found, it checks the **exact** name in the folder listing. macOS and Windows ignore case, so `Plot.PNG` opens when the paper says `plot.png`, but on Linux (and on the conference's server) it fails. In that case it returns the real file plus a warning note.
- If nothing matches exactly, it looks for a case-insensitive match.
- Returns `(path_or_None, note)`.
? Why compare against iterdir() instead of trusting is_file()?
! On a case-insensitive disk `is_file()` says yes for the wrong case. The folder listing shows the true spelling.
? Why is a case mismatch worth a warning?
! The paper compiles on the author's Mac but breaks on a Linux server, which is where submission systems run.

== _bring_inline_images
Images can also appear outside figures (inside a paragraph). This walks every non-figure block, finds each image, copies the file into `project/media/`, and rewrites the path in the tree to `media/<name>`.
? Why rewrite the path inside the node?
! The renderer writes LaTeX from the node later; the path must point to the copy inside our project folder.

== _bring_media
Copies every figure image of a LaTeX paper into `project/media/` and changes each figure's paths to the copies. A path that cannot be found is kept as it is (the analyzer then reports the figure as missing its image). Case warnings from `_resolve` become notes.
? Why copy images instead of using them where they are?
! The project folder must be self-contained: Prarup builds and exports from it, even if the original folder moves.

== _body
The main loop that decides what each block is. It uses a `while` loop with an index `i` (not a `for` loop) because one figure may swallow several blocks: images plus the caption after them. The rules are tried in order and the first that matches wins:
- A "References" heading or line: collect everything after it until the next heading into one references block (list items become separate entries).
- A Div: IEEE keywords become `m.keywords`; a bibliography Div becomes references.
- A real Header: a heading block.
- "Introduction:" on its own line, or a bold short paragraph: a heading, with `detected` saying why.
- A pandoc Figure (LaTeX figures): a figure with its images, caption and label.
- Image-only paragraphs: grouped together (sub-images). If the next block is a caption, it is joined; if the next block is a pandoc Figure with a caption, the sub-images are merged into it.
- In Word papers, a caption line with no image above: a figure with no image (reported later as "caption but no image").
- A Table: its caption, or a "Table 2:" paragraph just before or after it.
- An equation; otherwise a paragraph, quote, list, code or raw block. Horizontal rules are dropped.
The nested function `add(**kw)` creates a `Block` with the next id (`b1`, `b2`...). `counter` is a one-item list so the nested function can change it.
* Chain of rules: each `if` tries one rule and `continue`s when it matches, so a new kind of block is one new rule placed in the right order.
? Why is counter a list `[start_id]` and not a plain int?
! A nested function can change items inside an outer list, but assigning to an outer int would need `nonlocal`. The list is a simple way around that.
? Why a while loop instead of for?
! Some rules consume more than one block (a figure plus its caption). With `while` the code moves `i` forward by however many blocks were used.
? What is `**kw` in add?
! It collects keyword arguments into a dict and passes them on to `Block(...)`, so `add(kind="heading", level=1)` works.
? What happens to a table caption found in the paragraph before the table?
! That paragraph was already added as a block, so it is removed from `out` and used as the table's caption.

== _to_markdown
After `_body`, blocks still hold pandoc nodes. This converts their text to Markdown in **three** batched pandoc runs: one for body text, one for captions, one for reference entries. Then it hands the answers back in the same order with `next`.
- Caption prefixes like "Figure 2:" are stripped, because IEEE adds "Fig. 2." itself. The number found is kept in `b.number`.
- A leading `> ` (caption that was a block quote) is removed.
? Why strip "Figure 2:" from the caption?
! IEEEtran prints "Fig. 2." automatically; keeping it would print "Fig. 2. Figure 2: ...".
? Why three batches instead of one?
! Captions and references come back as separate lists, so they are easier to hand back to the right blocks.

== _tidy_paths
Removes a leading `./` from image paths, so `./media/x.png` and `media/x.png` are the same path everywhere.
? Where would "./" come from?
! LaTeX authors often write `\includegraphics{./figs/plot}`.

== open_paper
The entry point of the file. `Project.open` calls it.
- Checks the extension; only .docx, .tex and .zip are accepted.
- A zip is unpacked into `project/source/` and its main .tex found.
- pandoc reads the paper; Word images are extracted into the project.
- A new `Manuscript` is made; `api` (pandoc's version) is kept so later pandoc runs can be given the same version.
- Front matter, then `_body`, `_to_markdown`, `_tidy_paths`.
- For LaTeX: images copied, safe preamble lines kept, references read from `\bibitem`s (or the `.bbl` file), or from a `.bib` file which is copied in as `refs.bib`.
> open_paper("svm_messy.docx", folder) -> Manuscript(title="Support vector machine...", authors=[Author("Renas Rajab Asaad", ...)], abstract="", blocks=[b1 heading, b2 para, ...])
* Single Responsibility at file level is only partly kept: ingest.py both finds front matter and tags the body. It stays one file because both steps walk the same pandoc blocks; splitting it is a fair improvement to mention.
? What does open_paper return?
! A filled-in `Manuscript` object.
? What is the difference between how Word and LaTeX front matter is found?
! Word: by reading the first paragraphs (`_front_matter`). LaTeX: from pandoc's metadata plus the IEEE author blocks in the source (`_tex_front_matter`), falling back to the Word method if no title was found.
? Where do references come from in a LaTeX paper?
! A .bib file if there is one (copied in), else the `\bibitem` lines in the .tex, else the .bbl file LaTeX made.
