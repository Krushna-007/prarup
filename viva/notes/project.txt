@purpose
The **controller**: the one class the window talks to. The window never calls `ingest`, `renderer` or `checks` directly; it calls `Project` methods like `open`, `set_caption`, `build`, `fit` and `export`, and `Project` calls the right modules in the right order. This keeps the window code about buttons and the rest about papers.

A Project knows: the source file, its project folder (`<paper>-prarup/`, next to the paper), the `Manuscript` (`self.m`), the latest image reports, and the latest build result. **Every edit method saves `manuscript.json` immediately**, so nothing is lost if the app closes.

> Build:   render(m) -> paper.tex -> instrument -> Tectonic -> measure figures -> strip marks -> paper.pdf -> run_all_checks + small text
> Fit:     render(m) -> fit_paper("readable") [-> fit_paper("limit") if over the limit] -> name each change "Fig. N"
> Export:  build -> findings -> zip: paper.pdf, paper.tex, images, refs.bib, prarup-report.md, README.txt

@imports
Almost every module, because this is where they meet: `images` and `analyze` (what is missing), `checks` (PDF checks), `compile_pdf`, `find_graphics` and `instrument` (figures), `measure`, `fit_paper` and `describe`, `open_paper` (ingest), `Block` and `Manuscript`, `Author`, `Issue`, `Rules`, `render`. Plus `zipfile` for export, `shutil` to copy images, `date` for the report, `pymupdf` to strip marks and count pages.

== BuildResult
The result of one build: the PDF path (None if it did not compile), the PDF issues, the LaTeX log or error, and the page count. A dataclass.
? Why can pdf be None?
! When LaTeX fails no PDF exists; None makes "no PDF" explicit instead of a path to a file that is not there.

== BuildResult.ok
A property: True when a PDF was produced. Read as `result.ok`, without brackets.
? Why a property instead of a stored field?
! It is computed from `pdf`, so it can never disagree with it.

== Project
Holds one opened paper and everything done to it.

* Facade pattern: one simple class in front of many modules. The window calls `build()`; Project knows every step behind it. This is also Dependency Inversion in spirit: the window depends on Project's small set of methods, not on the modules.
== Project.__init__
Stores the source, the folder, the manuscript, an empty list of image reports and no build yet. Normally not called directly: use `Project.open`.
? Why is there both __init__ and open?
! `__init__` just stores ready-made parts. `open` does the work of finding or reading the manuscript, then calls `cls(...)`, which runs `__init__`.

== Project.folder_for
A **staticmethod**: the project folder for a paper is a folder next to it named `<stem>-prarup`. It needs neither `self` nor `cls`.
> folder_for(Path("/papers/svm.docx"))  ->  /papers/svm-prarup
? What is a staticmethod?
! A function that lives inside a class for organisation but gets no `self` or `cls`; it is called as `Project.folder_for(path)`.

== Project.open
A classmethod that opens a paper.
- If `manuscript.json` already exists and the source has not changed since (`source_mtime`), the saved manuscript is loaded, so the user's edits come back.
- Otherwise the paper is read fresh with `open_paper`, its modification time recorded, and saved.
- `fresh=True` forces a fresh read.
* Factory method: a classmethod that decides whether to load a saved manuscript or read the paper fresh.
? How does reopening a paper keep the user's edits?
! Edits are saved in `manuscript.json`; `open` loads that file instead of re-reading the paper, unless the paper file itself is newer.
? What does `source.stat().st_mtime` give?
! The time the file was last modified, as seconds since 1970.

== Project.save
Creates the folder if needed and writes `manuscript.json`.

== Project._block
Finds a block by id, or raises `KeyError` with a clear message. Private helper (leading underscore) for the edit methods.
* Fail fast: an impossible request raises at once instead of silently doing nothing.
? Why raise instead of returning None?
! An edit to a block that does not exist is a bug; failing loudly shows it at once instead of silently doing nothing.

== Project.set_front
Changes any of title, authors, abstract, keywords; `None` means "leave as it is". Authors may be given as `Author` objects or as `(name, affiliation)` tuples, which are converted with `Author(*a)`.
? Why do the parameters default to None and not ""?
! "" is a real value (clearing the field). None means the caller did not pass it, so it is left unchanged.

== Project.set_text
Sets a block's text and marks it `edited`; saves only if the text really changed.
? Why mark the block as edited?
! The renderer uses the original pandoc node for unedited blocks (exact) and re-reads the Markdown only for edited ones.

== Project.set_caption
Sets a figure's or table's caption and saves.

== Project.set_kind
Re-tags a block as heading, para or quote (the only kinds that can be swapped safely), sets its level, and records "re-tagged by you" in `detected`.
? Why only heading, para and quote?
! Their content is the same kind of thing (text). Turning a paragraph into a table or figure would need data it does not have.

== Project.delete
Removes the block from the list and saves.

== Project.move
Moves a block up (`step=-1`) or down (`+1`): `pop` removes it, `insert` puts it at the new position, which is clamped between the first and last place.
? What does `max(0, min(len(blocks) - 1, i + step))` do?
! Clamps the new position so moving the first block up or the last block down stays in range.

== Project._new_id
Finds the largest number used in ids like "b17" and returns the next one ("b18"). `default=0` handles a paper with no blocks.
? Why not use len(blocks) + 1?
! After deleting blocks, that number may already be in use; taking the maximum avoids duplicate ids.

== Project.insert
Creates a new block of the given kind after the given block (or at the start), marked as added by the user, and returns it so the window can select it.

== Project._import_image
Copies an image chosen by the user into the project's `media/` folder and returns its relative path. The name is cleaned (only letters, digits, dot, dash, underscore). If a **different** file with that name exists, a number is added (`plot-1.png`); the same file is not copied twice.
? Why clean the file name?
! Spaces and characters like `#` or `%` break LaTeX's `\includegraphics`.

== Project.set_image
Imports the image and puts it at position `index` in the figure (replacing that image), or appends it if `index` is past the end. A fitted width is cleared, because the new image may have a different shape.
? Why clear fit_width?
! The old width was chosen for the old image; the new one must be fitted again.

== Project.remove_image
Deletes one image from a figure and saves.

== Project.findings
Runs the image checks (keeping their reports for the Images tab and the figure cards) and the manuscript analyzer, and returns all findings. `classify` turns on the AI classifier.
? Why are image reports kept on the project?
! The window shows them in the Images tab and on each figure card without running the checks twice.

== Project.tex_path
The path of the generated `paper.tex` in the project folder.

== Project._figure_numbers
Maps each graphic's index in the LaTeX to its figure number in the paper. A figure can have several images, so graphic 5 may belong to Fig. 4. Images outside figures map to None.
? Why are graphic index and figure number different?
! The index counts every `\includegraphics`; a figure with two images uses two indexes but is one figure.

== Project.build
Builds and checks the PDF:
- render the manuscript to `paper.tex`;
- compile an **instrumented** copy (graphics wrapped in markers) once;
- if no PDF came out, return a BuildResult with the readable LaTeX error;
- measure figure positions and text sizes, then remove the markers (`_strip_marks`) to make the clean `paper.pdf`;
- run all PDF checks plus the small-figure-text check (GEOM-03), count pages, and remember the result.
? Why compile the instrumented copy instead of compiling twice?
! One compile gives both the measurements (from the marker links) and the PDF (after removing the links). Compiling twice would double the waiting.
? What is GEOM-03?
! A figure whose text prints smaller than 7 pt, found from the measurements. It tells the user to use Fit figures.

== Project.fit
Renders `paper.tex`, runs the fitter with the readable policy, and if that layout is over the page limit, also with the limit policy (kept only if it really has fewer pages). Each change is named by its figure number ("Fig. 4"), or "Image in the text". Returns one or two FitReports for the window to choose from.
? Why can it return two options?
! Readable figures and the page limit can conflict. Prarup does not decide; it shows both and the user picks.

== Project.apply_fit
Reads the fitted LaTeX, and for each single-image figure copies its new width and its figure/figure* choice back into the manuscript (`fit_width`, `double`), so later builds keep the fitted layout.
? Why store the width in the manuscript instead of keeping the fitted .tex?
! The .tex is regenerated on every build. Storing the choice in the manuscript means it survives edits and rebuilds.

== Project.report_markdown
Writes the report included in the export: missing items, image findings and PDF issues as bullet lists ("All clear." when a section is empty), then a table of every figure image with pixels and dpi.

== Project.export
Builds, refuses if the paper does not compile, runs the findings, then writes a zip with the PDF, the LaTeX, every image the LaTeX uses (found with a regex over `\includegraphics`), the .bib if there is one, the report and a README.
* Single Responsibility kept at method level: export reuses `build` and `findings` instead of repeating them (DRY).
? Why build again inside export?
! So the zip always matches the current manuscript, even if the last build is older than the latest edit.
? How does it decide which images go in the zip?
! It reads the image paths from `\includegraphics` in the final paper.tex, so unused images are left out.

== _strip_marks
Copies the measured PDF to `paper.pdf` without the invisible `prarup:fig:N` links. `garbage=3, deflate=True` removes unused objects and compresses the file.
? Why remove the links?
! They exist only for measuring. The paper sent to a conference must not contain strange invisible links.

== _small_text
Turns measurements into GEOM-03 issues for each figure whose text is below the minimum (with 0.05 pt tolerance for rounding), named by figure number.
? Why the 0.05 tolerance?
! Measurements like 6.97 pt are rounding noise from a figure fitted to exactly 7 pt; they should not be reported.

== _readable_error
Turns Tectonic's long log into one readable sentence: finds the first real error line, the line number in paper.tex, and the message. Falls back to the end of the log.
> "error: paper.tex:212: Undefined control sequence"  ->  "LaTeX stopped at line 212 of paper.tex: Undefined control sequence"
? Why skip lines mentioning "XeTeX engine" or "something bad"?
! Those are Tectonic's generic wrapper messages; the real error is the line before them.
