@purpose
Writes the `Manuscript` as an **IEEE LaTeX paper** (`paper.tex`). It does not copy the author's LaTeX: it rebuilds the paper in our own template (`templates/ieee.tex.j2`), which is why real papers written for other engines compile.

How it works, in three steps:
- every short text (headings, captions, references, title block) and every table cell is converted from Markdown to LaTeX by pandoc, **in batches**;
- each block becomes a piece of LaTeX: `\section{...}`, a figure environment, a table, an equation, a bibliography; paragraphs are converted by pandoc;
- the pieces are poured into the template with **Jinja2**.

Jinja2 normally uses `{{ }}` and `{% %}`, which clash with LaTeX's braces, so `_env` changes them to `\VAR{...}` (insert a value) and `\BLOCK{...}` (if/for). The template also writes the page geometry into the PDF (`PrarupGeometry`) so figure checks can read the real column width.

Patterns: `_NUMBERING` strips typed section numbers ("2.1 ", "III. ") because IEEE numbers sections itself; `_UNNUMBERED` lists sections IEEE leaves unnumbered (Acknowledgment, Appendix); `_ALIGN` maps pandoc's column alignment to LaTeX's l/r/c.

@imports
`re`, `Path`, `jinja2` (the template engine), `pandoc` (Markdown to LaTeX) and `Manuscript`.

== _env
Creates the Jinja2 environment with LaTeX-friendly markers and options: `trim_blocks` and `lstrip_blocks` remove the blank lines `\BLOCK` lines would leave, `autoescape=False` because the values are already LaTeX, and `FileSystemLoader` finds templates in the `templates` folder.
* Separation of concerns: the layout of the paper lives in the template, the logic in Python.
? Why change Jinja's {{ }} markers?
! LaTeX uses braces everywhere (`\textbf{...}`), so `{{` would appear in normal LaTeX and confuse Jinja. `\VAR{}` never does.
? Why autoescape=False?
! Autoescape is for HTML (it would turn `<` into `&lt;`). Our values are LaTeX already.

== _plain_heading
Removes a typed number from the start of a heading ("2.1 Methods" becomes "Methods") and un-escapes `\.`.
? Why strip "2.1"?
! IEEEtran numbers sections itself; keeping it would print "II. 2.1 Methods".

== _flatten_tables
A table inside a table cell cannot be written in LaTeX. This replaces any nested table with one line of its text, cells joined by "; ".
? Where did a nested table come from?
! A real Word paper had a table inside a table cell; the LaTeX failed until it was flattened.

== _bounded
Returns a deep copy of the blocks with every image's width and height removed. Word stores sizes in inches that can be wider than an IEEE column; without them pandoc writes `\pandocbounded`, which scales the image to fit. `copy.deepcopy` is used so the saved manuscript is not changed.
? Why deepcopy and not copy?
! The images are nested deep inside lists and dicts; a shallow copy would still share them, and removing widths would change the saved manuscript too.

== _cells
For one pandoc table: every row as a list of `(alignment, column_span, content_blocks)` tuples, plus the number of header rows. A cell in pandoc is `[attr, alignment, row_span, col_span, blocks]`.
? What is a column span?
! How many columns a cell covers; a heading cell over two columns has span 2 and becomes `\multicolumn{2}`.

== _table_latex
Writes one table as LaTeX, deciding its width from its content.
- `longest` holds the longest text in each column (LaTeX commands removed).
- `natural`: an estimate of the table's natural width in points (4.5 pt per character, capped at 60 characters, plus 12 pt padding per column). One IEEE column is 252 pt wide.
- Wider than 1.6 columns: `table*`, spanning both columns.
- Wider than one column: long columns become wrapping `X` columns of `tabularx`.
- Otherwise a plain `tabular` inside `adjustbox`, which shrinks it if it is still too wide.
- A `\midrule` goes after the header rows; `\toprule` and `\bottomrule` (booktabs) frame it.
- Cell LaTeX was computed earlier in one pandoc batch and is looked up by `(id(row), n)`.
? How does it decide between table and table*?
! It estimates the table's natural width from the longest text in each column; more than 1.6 column widths means it spans both columns.
? Why not use pandoc's own table output?
! pandoc writes `longtable`, which is illegal in a two-column IEEE paper. Every real Word paper failed to compile because of it.
? What does `(id(r), n)` identify?
! A cell: `id(r)` is the identity of its row list and `n` its position in the row.

== _figure_latex
Writes one figure. Each image gets an `\includegraphics` with a width: the width chosen by Fit figures if there is one, otherwise an equal share of the column (0.98 divided by the number of images). A missing image, or a format LaTeX cannot place, becomes a visible framed box saying "image missing", so the paper still builds and the gap is obvious. `figure*` is used when the fitter chose two columns.
? What happens when an image file is missing?
! A framed placeholder box with "image missing" and the file name is printed instead, so the PDF still builds.
? Why `0.98` of the column and not 1.0?
! A little room is left so the figure never touches the column edge or the neighbouring column.

== _references_latex
Writes the reference list: `\bibliography{refs}` with the IEEE style when a .bib file was copied in, otherwise a `thebibliography` list of `\bibitem`s. Keys are the paper's own keys or `ref1`, `ref2`...; a typed "[3] " at the start of an entry is removed because LaTeX numbers them.
? Why remove "[3]" from each entry?
! `thebibliography` prints the numbers itself; keeping them would print "[3] [3] ...".

== body_latex
Builds the LaTeX of the whole body.
- Paragraphs the user **edited** are re-read from their Markdown (`markdown_to_blocks`); untouched paragraphs use their original pandoc nodes, which lose nothing.
- All short texts (headings, captions, references) go to pandoc in one batch; all table cells in another.
- Each block then becomes a `RawBlock` of LaTeX, or its pandoc nodes. Headings choose `\section`, `\subsection`... by level; equations are wrapped in `equation` unless they already are an environment.
- Finally the whole list goes to pandoc once more to produce LaTeX, and nested maths environments are fixed by `_unwrap_environments`.
? Why use the original pandoc node for unedited paragraphs?
! Converting to Markdown and back can lose details (footnotes, special characters). The node is exact; only edited text needs re-reading.
? What is a RawBlock?
! A pandoc node that says "this is already LaTeX, copy it as it is".

== _unwrap_environments
Some papers put an `align` environment inside `\[ ... \]`, which LaTeX rejects. This removes the outer `\[ \]` and moves any `\label` that was outside onto the first line of the equation that has no label yet (a line can only have one label).
- The nested `place` function rebuilds each match: environment start, body (with the label added), environment end.
? Why move the label?
! LaTeX allows only one `\label` per equation line; putting it on a line that already has one causes an error.

== _lines
Breaks a long affiliation into several lines at commas, each at most about 45 characters, joined with LaTeX line breaks `\\`. Short affiliations are returned unchanged.
? Why break affiliations?
! In the IEEE title block, a long affiliation on one line overflows into the neighbouring author's column.

== render
The entry point. Converts the title, abstract, keywords and every author name and affiliation to LaTeX in **one** pandoc call (people come back as name, affiliation, name, affiliation... and are paired with `range(0, len(people), 2)`), builds the body, and fills the template.
* Open/Closed: the template is a parameter (`template="ieee"`); another format is a new `.tex.j2` file, with no change to the renderer's Python code.
? Why convert all the front matter in one call?
! Each pandoc start costs time; one call for everything is much faster than one per field.
? What does `range(0, len(people), 2)` do?
! Counts 0, 2, 4...: the position of each name; `people[i + 1]` is that author's affiliation.
