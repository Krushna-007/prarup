@purpose
pandoc loses a few things when it reads LaTeX: IEEE author blocks, `\bibitem` reference lists, `.bib` files and the author's own macros. This file reads them **straight from the LaTeX source text** with small hand-written parsers.

Two patterns at the top: `_INPUT` finds `\input{file}` and `\include{file}`; `_COMMENT` finds a `%` comment to the end of the line, but not an escaped `\%` (the `(?<!\\)` part is a "lookbehind": "not preceded by a backslash").

@imports
`re` for the patterns, `Path` for files. No other Prarup module: this file only reads text.

== full_source
Returns the whole paper as one string, with every `\input{...}` replaced by that file's contents (recursively) and comments removed.
- `seen` remembers files already included, so a file that includes itself cannot loop forever.
- The nested `inline` function is used as the replacement for each `\input` match: it tries `name` and `name.tex` and calls `full_source` on it.
* Recursion with a visited set: the classic guard against cycles in a graph of files.
? Why the seen set?
! Without it, two files that `\input` each other would recurse forever and crash.
? Why `seen if seen is not None else set()` instead of a default `seen=set()`?
! A default value is created once and shared by every call; a mutable default would keep files from an earlier paper. Making a new set each call avoids that classic Python trap.

== _group
Given the position of an opening `{`, returns what is inside the matching `}` and the position just after it. It counts depth: `{` adds one, `}` subtracts one, and depth 0 means the group closed.
> _group("\\textbf{a{b}c} rest", 7)  ->  ("a{b}c", 14)
? Why not use a regex for braces?
! Regular expressions cannot count nested brackets. A simple counter handles any depth.

== _command_args
Finds every `\command{...}` and returns the contents of the braces, using `_group` so nested braces are handled. `(?=\{)` is a lookahead: the command must be followed by `{`, which is not consumed.
? What is a lookahead?
! `(?=...)` checks what comes next without including it in the match.

== ieee_author_blocks
Reads `\author{...}`, then the `\IEEEauthorblockN{name}` and `\IEEEauthorblockA{affiliation}` inside it, and pairs them by position. If there are no IEEE blocks, the whole author text is returned as one entry.
> [("Asha Rao$^{1}$", "Dept. of CS\\\\ DA-IICT"), ("Ravi Mehta", "...")]
? What if there are more names than affiliation blocks?
! The extra names get an empty affiliation (`places[i] if i < len(places) else ""`).

== bibitems
Reads a `thebibliography` environment: finds its body, splits on `\bibitem`, and for each item takes the key in braces and the rest as the text. Returns `(key, text)` pairs.
> \bibitem{smith20} J. Smith, "FL at the edge", 2020.  ->  ("smith20", "J. Smith, \"FL at the edge\", 2020.")
? Why `[1:]` after re.split?
! The part before the first `\bibitem` is not an item (it is the `{99}` width argument), so it is dropped.

== bib_keys
Returns every key of a .bib file: the word after `@article{` and before the comma.
? What does re.findall return when the pattern has one group?
! A list of what the group matched, here the keys.

== bibliography_files
Finds `\bibliography{refs,extra}` and returns the file names, split on commas.
? Why split on commas?
! LaTeX allows several .bib files in one command.

== bib_entries
A small .bib reader. For each `@type{key,` (skipping @comment, @string, @preamble), it finds the entry body with `_group`, then reads each `field = value`, where the value may be `{braced}`, `"quoted"` or bare (up to a comma or newline). Returns `(key, fields_dict)` pairs.
- `fields.setdefault(name, value)` keeps the first value if a field appears twice.
? What does setdefault do?
! Sets the key only if it is not already there, and returns its value.
? Why skip @string and @comment?
! They are not references; they are .bib file housekeeping.

== describe_entry
Writes one reference as text from its fields: authors, title in quotes, venue in italics, year. Empty parts are left out.
> {"author":"A and B","title":"T","journal":"J","year":"2020"}  ->  "A, B, ``T'', \\emph{J}, 2020."
? Why ``'' instead of normal quotes?
! In LaTeX, two backticks and two apostrophes make proper curly quotes.

== preamble_extras
Keeps the safe parts of the author's preamble so their maths still compiles in our template.
- Only packages in `SAFE_PACKAGES` (maths, algorithms, tables) are kept. Packages that change the page layout (geometry, fonts, inputenc) are dropped, because they would break the IEEE format or the XeTeX engine.
- Every `\newcommand`, `\def`, `\DeclareMathOperator` etc. is copied whole: the loop after the command name skips over `{...}` and `[...]` groups until the definition ends.
- `\newcommand` is changed to `\providecommand`, which does nothing if the command already exists, so a clash with our template cannot stop the build.
? Why not copy the author's whole preamble?
! A pdfLaTeX-only package such as inputenc stopped real arXiv papers from compiling with Tectonic (XeTeX). Copying only safe lines fixed that.
? What is the difference between \newcommand and \providecommand?
! `\newcommand` fails if the name exists; `\providecommand` quietly keeps the existing one.
