@purpose
All **colours and widget styles** in one place. The app is always light, with every colour set explicitly, so it looks the same on Windows, Linux and macOS, including macOS dark mode (which made dark text on a black list in the first Tkinter version). The constants at the top are the palette: background, panel white, ink, muted grey, line, the orange accent `#e8590c`, the selection tint, red for errors and amber for warnings.

@imports
`tkinter`, `font` (the system's default font) and `ttk` (themed widgets and their styles).

== apply
Styles the whole app. Uses the system's default font (so it is right on every OS, unlike a hard-coded "Segoe UI" that only Windows has) and the `clam` theme, which lets us set colours. Then configures each named style: `TButton`, `Accent.TButton` (the orange Build button), `Danger.TButton`, `Treeview` and its heading, notebook tabs, labels for titles, hints, problems and the status line. `style.map` sets colours for states such as active (mouse over), selected or disabled.
* Single source of truth: every colour and style is defined once here; no other file hard-codes a colour name.
? What is a ttk style name like "Accent.TButton"?
! A named variant of the button style: `Accent` is our name, `TButton` the base it inherits from. A widget uses it with `style="Accent.TButton"`.
? Why the clam theme?
! The macOS native theme ignores most colour settings; `clam` obeys them on every platform.
? Why not hard-code a font family?
! A font like Segoe UI exists only on Windows; the system default font is right everywhere.

== text_box
Creates a multi-line `tk.Text` with every colour set (background, text, cursor, selection), a thin border and padding, filled with a starting value. Classic Tk widgets (not ttk) take colours directly.
? Why set insertbackground?
! It is the cursor colour; in dark mode Tk would draw a white cursor on our white box, making it invisible.

== entry
Creates a single-line `ttk.Entry` filled with a value.
